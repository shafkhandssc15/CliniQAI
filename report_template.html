Executive Summary

Medical diagnostic errors and laboratory report interpretation delays remain significant clinical bottlenecks across high-volume healthcare centers and outpatient dispensaries in Sri Lanka. CliniQ AI was engineered to bridge this gap by delivering a unified, zero-latency clinical AI workstation. The platform analyzes diverse laboratory investigations—including Full Blood Counts (FBC/CBC), Comprehensive Metabolic Panels, Liver Function Tests (LFT), Renal Function Tests (KFT), Glycemic Profiles, Lipid Panels, and Thyroid Panels—and converts raw optical documents into structured biomarker intelligence, multi-model consensus diagnoses, and personalized clinical action plans.

Core Engineering Philosophies

  • Multi-Engine Consensus over Single-Model Fallibility: Medical decisions cannot rely on a single probabilistic neural network. CliniQ AI arbitrates across four orthogonal paradigms: deterministic expert rules, an ultra-low latency supervised tree ensemble (XGBoost), and two cloud vision-language foundation models (Gemini 2.5 Flash and NVIDIA NIM Llama 3.2 Vision).
  • Strict Non-Autonomous Doctrine: AI generates differential candidates, anomaly indices, and clinical cautions; however, report finalization strictly requires verified SLMC physician authorization.
  • Zero-Config Offline Resilience with Cloud Hybrid Sync: Fully functional offline using local EasyOCR, local SQLite, and local XGBoost models, while seamlessly streaming telemetry and dossiers to Supabase PostgreSQL when connectivity is available.
  • Sri Lankan Clinical Localization: Purpose-built regex parsers for Sri Lankan National Identity Cards (NIC), Sri Lanka Medical Council (SLMC) registrations, telephone formats, and trilingual patient name recognition (English, Sinhala, Tamil).

SAFETY GUARDRAILS & DISAGREEMENT PENALTY
  • Rules Engine Safety Veto: The rules engine acts as a primary clinical safety circuit breaker. Life-threatening emergency thresholds immediately override probabilistic ML and VLM votes, escalating urgent alerts.
  • Definitive "Healthy" Guardrail: If laboratory biomarkers show verified pathology (e.g., FBS ≥ 126 or Hb < 12), all conservative "Healthy" or "Normal" model votes are forcefully purged from voting weights.
  • Disagreement Penalty & Abstention: When models disagree without definitive critical lab pathology, confidence is penalized into the decision-support band (< 70%), and the engine explicitly abstains while providing specific confirmatory lab tests (HbA1c, OGTT, Iron profile, FBC monitoring) to resolve the conflict.
  • Sri Lanka PDPA (2022) Privacy Layer: Cloud VLMs (Gemini & NVIDIA) receive client-side de-identified images with patient Name, NIC, Phone, and Address redacted via bounding-box masking before transmission.

Longitudinal Trend Engine & Deterioration Alerts

When a patient's historical reports exist in the database, the longitudinal engine retrieves the last 5 records and computes analyte delta (Delta), trajectory slope (Rising, Falling, Stable), and generates automated deterioration alerts:

  • Acute Bleeding Alert: Haemoglobin drop of 1.5 g/dL or more since last encounter triggers immediate occult GI blood loss evaluation.
  • Acute Kidney Injury (AKI) Alert: Serum Creatinine increase of 0.3 mg/dL or more triggers nephrotoxic drug cessation and hydration protocol.
  • Glycemic Deterioration: Fasting blood sugar surge of 30 mg/dL or more triggers prompt therapeutic intensification.
  • Thrombocytopenic Crash: Platelet count decline of 50 x 10^3/uL or more triggers dengue/hematologic review.

5. Computer Vision, EasyOCR & Multilingual Parser

Laboratory reports in Sri Lanka are produced across hundreds of different laboratory formats with varied fonts, contrast ratios, and table layouts. ocr_engine.py implements a robust spatial bounding-box clustering algorithm coupled with intelligent unit-aware regex parsers.

Spatial Line Reconstruction Algorithm

1. EasyOCR reader processes image bytes (auto-detects NVIDIA CUDA GPU vs CPU).
2. For each detected bounding box: compute vertical center (y_center) and height (h).
3. Group boxes into horizontal lines: boxes belong to the same line if:
   |box.y_center - line.y_average| <= max(10.0, line.height_average * 0.65)
4. Sort lines top-to-bottom by y_center.
5. Sort words within each line strictly left-to-right by x_min.
6. Concatenate words into reconstructed lines.

Smart Biomarker Extraction (Range-Sanitization Logic)

Standard OCR regular expressions frequently fail because they accidentally match the laboratory's printed reference range (e.g. 12.0 - 17.5) instead of the patient's actual result (e.g. 9.2). CliniQ AI solves this with a 4-tier extractor (extract_smart_biomarker):

  1. Unit-Proximity Matching: Searches for numbers immediately preceding recognized clinical units (g/dL, x10^3/uL, mg/dL, mIU/L, U/L).
  2. Reference Range Sanitization: Replaces bracketed ranges ([0.55 - 4.78]), hyphenated ranges (12.0 - 16.0), and biological reference strings with a neutral [REF_RANGE] token.
  3. Cleaned Line Search: Extracts candidate numeric values from the range-sanitized text within physiological sanity limits.
  4. Left-to-Right Fallback: If step 1–3 fail, sequentially inspects candidate numbers within defined plausible medical bounds.

Supabase Cloud Integration Highlights

  • Direct PostgREST API: Communicates over HTTP/2 using httpx.AsyncClient, avoiding heavy external Python SDK incompatibilities while guaranteeing non-blocking async operation.
  • Strict Row Level Security (RLS) & Multi-Tenant Doctor Isolation: The Supabase schema (supabase_schema.sql) enforces true physician isolation checking both Supabase Auth UID and signed JWT subject claims: 
    CREATE POLICY "Doctor isolated read patient_reports"
ON public.patient_reports FOR SELECT TO authenticated, anon
USING (
    doctor_id = auth.uid()::text 
    OR doctor_id = (current_setting('request.jwt.claims', true)::jsonb ->> 'sub')
);
  • Optimized Indexing: Composite indices on (doctor_id, created_at DESC) and patient_ref ensure sub-50ms query latency for clinic report retrieval and longitudinal delta lookups.
  • Automatic Dual-Sync: Every report analyzed via /api/analyze and every doctor sign-off via /api/reports/{ref}/review is automatically synced to Supabase Cloud in the background without blocking the UI response.

7. Security, Authentication & Medical Legal Governance

Operating in the clinical domain requires stringent data governance, legal safety barriers, and authentication protocols. CliniQ AI adheres to the Sri Lanka Personal Data Protection Act (PDPA) No. 9 of 2022, Sri Lanka Medical Council (SLMC) ethical guidelines, and international clinical software safety standards.

Data Privacy & Sri Lanka PDPA (2022) De-Identification

PRE-TRANSMISSION PATIENT PII REDACTION
Under the Sri Lanka Personal Data Protection Act No. 9 of 2022, transmitting identifiable health data across international boundaries without explicit de-identification is restricted. CliniQ AI runs a local optical de-identification layer (deidentify_report_image in ocr_engine.py) using Pillow and EasyOCR bounding boxes. Prior to dispatching report scans to cloud VLMs (Google Gemini, NVIDIA NIM), all bounding boxes containing Patient Name, Sri Lankan NIC (9-digit/12-digit), Phone Numbers, and Street Addresses are dynamically redacted with opaque black masking. Cloud models remain entirely blind to patient identity.

Tamper-Evident Cryptographic Audit Logging

Standard database tables named "immutable" are vulnerable to administrative manipulation. CliniQ AI implements a cryptographic blockchain-style hash chain (auth.py, compute_audit_hash()): 

H_0 = SHA256( "GENESIS" | event_type | actor_id | target_id | timestamp | details )
H_n = SHA256( H_{n-1}   | event_type | actor_id | target_id | timestamp | details )

Every entry stores prev_hash and row_hash. Any retroactive row modification or deletion breaks the hash chain for all subsequent entries, creating mathematical tamper-evidence.

Brute-Force Protection & Session Hardening

  • In-Memory Rate Limiting: Enforces a strict 5-attempt threshold within a sliding 15-minute window per SLMC license or IP address. Breaching triggers a 15-minute automated lockout with HTTP 429 response.
  • Session Token Rotation: Re-authentication automatically revokes prior active JWT sessions, preventing concurrent token hijacking across public clinic terminals.
  • Production Secret Safeguard: The application programmatically halts boot if ENVIRONMENT=production and CLINIQ_SECRET_KEY is left as the default or shorter than 32 characters.

Sri Lankan Credential Verification Algorithms

Unlike generic platforms that accept arbitrary strings, CliniQ AI verifies all clinical practitioner identities at registration (auth.py):

Identifier Algorithmic Rule / Pattern Normalization Output Error Handling
SLMC Registration Regex ^SLMC[-\/]\d{4,6}$ verifying official Sri Lanka Medical Council license. SLMC-XXXXX (Standard uppercase hyphenated) Rejects with REG_001 if format fails; enforces database uniqueness.
Sri Lankan NIC (Legacy) Regex ^(\d{9})[VXvx]$. Validates 2-digit birth year and day-of-year (1–366). XXXXXXXXXV (Uppercase) Validates day-of-year math (>500 indicates female); rejects invalid calendar days.
Sri Lankan NIC (Modern) Regex ^(\d{12})$. Validates 4-digit birth year (1900–present) and day-of-year. XXXXXXXXXXXX Rejects implausible birth years and malformed day counts with REG_002.
Mobile Phone Regex ^(\+94|0)[0-9]{9}$. Strips whitespace, dashes, and formats. +94XXXXXXXXX (E.164 international) Rejects non-Sri Lankan standard mobile formats with REG_006.

Physician Digital Sign-Off Protocol

  • Confirmation: Doctor agrees with the consensus diagnosis and locks the record.
  • Modification: Doctor overrides the diagnosis, enters clinical justification notes, and saves the modified diagnosis.
  • Rejection: Doctor rejects the AI analysis (e.g. poor image quality, artifact, clinical mismatch) and documents the clinical rationale.

Honest Observations & Technical Weaknesses Documented

  • Infection Uncertainty (67% Abstention Rate): Infection detection from isolated white-cell parameters is inherently ill-posed because viral pathogens frequently present with normal WBC. The engine abstains (67% uncertainty) rather than issuing dangerous uncalibrated predictions.
  • Hypercholesterolemia Overlap: Exhibits the lowest decision sensitivity (0.68) because borderline clinical lipid distributions intentionally overlap healthy reference bounds.
  • Analyzer Shift & Site Recalibration: When evaluated on an unseen external laboratory with calibration drift, negative coverage drops to 0.74–0.79 for CKD and Anemia. Executing recalibrate_site using local physician sign-off labels completely restores negative coverage to 0.89–0.94 across all conditions.
  • Assessability Guard: When entire panels are absent, legacy classifiers misclassified 7–15% of positive cases as "healthy". CliniQ Engine v2.2 enforces an assessability guard that drops this false negative rate to 0.0% by strictly refusing to predict without mandatory inputs.
  • OCR Decimal Slip Cross-Checking: Single-field physiological bounds and identities catch 64% of 10× slips; the remaining slips are surfaced via dual-reader cross-checking (verify.cross_check_extractions) between EasyOCR and VLM before physician analysis is finalized.

10. Code Quality, Gap Analysis & Strategic Roadmap

An engineering audit was conducted across all 34 source files to identify architectural strengths, potential technical debt, and priority enhancements.

Key Architectural Strengths

  • Resilient Fallback Design: When cloud VLM keys are missing or network outages occur, the system gracefully degrades to local EasyOCR and XGBoost without crashing.
  • High Performance: Pure vanilla JavaScript frontend with zero heavy runtime overhead loads instantly; local ML model infers in 0.0066 milliseconds.
  • Strict Type Safety & Schemas: Extensive use of Pydantic models (routes_auth.py, routes_reports.py, routes_admin.py) and SQLAlchemy mapped columns ensures strong type validation.
  • Evidence-Based Clinical Logic: Implements accredited medical scoring equations (WHO, ACC/AHA, CKD-EPI, ATA, ATP III) rather than relying solely on black-box LLM hallucinations.
  • Automated Test Rigor: Comprehensive 14-test automated pytest harness guarantees non-regression across security, consensus, and clinical guidelines.
